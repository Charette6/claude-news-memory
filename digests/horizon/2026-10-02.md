## AI & autonomous systems

### An AI agent broke into a Dutch security nonprofit using two zero-days, and left its reasoning in the code

Slug: `divd-agentic-zero-day-intrusion` (feed: The Register; primary via search)

DIVD (Dutch Institute for Vulnerability Disclosure) case DIVD-2026-00014, latest update 1 October: initial access 21 September, detected and datacenter access blocked 22 September, public disclosure 24 September, zero-days identified 30 September, breach overview published 1 October. The attacker chained CVE-2026-102489 (unauthenticated RCE and session leakage in Zammad helpdesk, CVSS 9.4; exploitable in 6.3.0-6.5.4, present but not exploitable in 7.0.0-7.1.3) and CVE-2026-102490 (local privilege escalation to root, CVSS 9.4; all versions from 1.5.0) to hijack sessions, execute code and reach root "in seconds", then pivoted to other services and exfiltrated volunteer email addresses and possibly contact details. Network segmentation stopped deeper movement. DIVD calls it an "agentic AI powered attack": scripts contained "notes where the agent justifies its own actions", the attack was "loud and very messy, with the agent working automated and deciding each next step itself at speed", and the agent "polluted its own MITM attack with password spraying". Operator and motive unknown. DIVD advises upgrading Zammad to version 7 or taking it offline.

Why it matters: a documented case of an agent exploiting previously unknown vulnerabilities against a real organisation, with a verbose trail. Internet-facing helpdesk and ticketing systems are a reachable target class; segmentation was the control that held.

Confidence: event, moderate (attribution to an agent is DIVD's inference from the artefacts; operator unknown).

### AWS open-sources a history-aware allow/deny gate for agent tool calls; Classie ships inline agent controls the same day

Slug: `aws-dogwood-local-engine` (feed: The Register; AWS primary and Classie via search sweep)

AWS Open Source blog, 30 September: the Dogwood Local Engine is an Apache 2.0 Rust library implementing an authorisation engine for the Dogwood policy language AWS published in August. A harness intercepts each tool call, submits a request event, and runs the tool only on an allow verdict; response events record outcomes so policies can reference the agent's past actions and their results (example: permit git push only if tests passed within 15 minutes and none failed since). AWS reports about 20 microseconds per decision with 15-minute windows and 6 milliseconds with 24-hour windows; fine-grained action schemas were about five times faster than coarse ones. Stated limits: the engine does not isolate anything (OS-level sandboxing is the harness's job), its internal log is checkpointed and pruned and "cannot be relied upon to audit past actions", and it cannot reason about events not sent to it. Repository is published under amazon-archives.

Classie (GlobeNewswire, 1 October) announced general availability of Supervise: an Open Policy Agent policy engine with lightweight sensors enforcing rules inline across endpoints, browsers and enterprise compute, with sensitive-data detectors and "Supervisor agents" that can "alert, restrict, reroute or stop an agent action as it happens", plus a runtime transcript tying actions to user identity, data touched and spend. Two anonymised case studies (healthcare, an AI company); no financial customers named.

Why it matters: history-aware allow/deny on agent actions is now an open-source building block and a commercial product on the same day. It is the control pattern to ask agent builders and vendors to demonstrate.

Confidence: announcement, moderate (vendor claims; not independently tested).

### LLMLeak: covert exfiltration through legitimate LLM web fetching

Slug: `llmleak-web-fetch-exfiltration` (feed: arXiv cs.CR)

arXiv 2610.01768, submitted 1 October: malicious local software embeds secrets in URLs presented to an LLM assistant as resources for a benign task (e.g. library migration); the assistant's web-fetch delivers them to attacker DNS or web servers. 79.7% attack success across eleven open-parameter models, with assessments on unnamed real-world chatbots.

What would make it matter: confirmation against a deployed enterprise assistant with web fetching enabled.
