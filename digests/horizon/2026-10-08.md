## AI & autonomous systems

### Windows now ships an OS-level agent sandbox, and Copilot that acts on local files

Slug: `windows-mxc-agent-containment-copilot-files` (feed: The Register, The Verge, Fortune, Ars Technica, Microsoft Source, NVIDIA; Microsoft primary via Microsoft Source link index).

Windows Developer Blog, "Microsoft Execution Containers: Policy-driven containment for AI agents" (7 October): MXC is "a policy-driven execution layer for untrusted code or dynamically generated workloads", now generally available on Windows 11. Backends: process container (AppContainer on Windows, Seatbelt on macOS, Bubblewrap on Linux), session container (separate Windows account and session), WSL container, and an experimental microVM. Developers declare the files and network destinations a workload needs; "the policy remains outside the agent workload's control". Three modes: enforcement, learning (blocks and records to a JSON activity report), permissive (allows and records). No end-user approval flow is described. Integrated now: GitHub Copilot, OpenClaw, OpenAI Codex, Replit, LM Studio, Unsloth AI; NVIDIA has integrated OpenShell into MXC. Announced as coming: Anthropic Claude Code, Box, Egnyte, Hermes Agent, Manus, Perplexity, Raycast, Simular and others. "Intune policy will soon be available to manage MXC process containers"; Windows will "soon enable Microsoft Entra to help distinguish agent activity from user activity" and extend Agent 365 controls to local agents. No dates for the Intune or Entra pieces.

Windows Experience Blog, "Building Windows for hybrid intelligence" (7 October, Pavan Davuluri): "With your permission, Copilot can understand relevant content on your PC, including files and recent activity"; Copilot can organise files, check diagnostics, troubleshoot and code, and "Autopilot" is a persistent agent that keeps working in the background. Hybrid features roll out "over the coming months on Copilot+ PCs"; taskbar Copilot integration is opt-in and reaches select markets later this year. Microsoft calls Windows "the most secure platform for agents". A footnote says "Governance at scale may require additional services." The Register (7 October) notes Copilot's agentic features will not have access to the entire file system and will search documents only "if you ask it to", and that the announcement does not describe enterprise controls.

Why it matters: a new control class (OS-level, policy-enforced agent containment) is now built into the endpoint OS banks run, but the management plane IT would use to govern it is not yet shipped, while first-party and third-party agents that act on files are arriving on the same timeline. Decide whether endpoint policy blocks agent harnesses or waits for the Intune controls.

Confidence: announcement, high (Microsoft primary posts; enforcement claims are the vendor's).

### UPDATE: AWS releases Strands Box, an open-source agent sandbox with history-aware rules

Slug: `aws-strands-box-agent-sandbox` (feed: The Register; AWS primary via Register link). Update to `aws-dogwood-local-engine` (2 October).

AWS Open Source Blog, "Introducing Strands Box" (7 October): "an open source sandbox licensed under Apache 2.0", in developer preview, that combines OS-level isolation (macOS Seatbelt) with policies evaluated by the Dogwood Local Engine "against an agent's requested action and recorded history". "Permissions can depend on earlier actions, their order and limits accumulated over time" (example: three Slack posts per ten minutes, counting only HTTP 200 responses). Enforcement points: network egress gateway, a Python interpreter (Monty), a shell interpreter (Strands Shell) and an MCP broker, together governing file reads and writes, shell commands, HTTP methods and paths, and MCP tool calls. The egress gateway can inject credentials so the agent never sees the real secret. Denied requests get an HTTP 403 naming the rule. No human-approval step is described. "We're starting with macOS"; future plans include packaging agents with Box for Amazon Bedrock AgentCore, ECS or Kubernetes. The Register (7 October, 18:42 UTC) quotes AWS: the agent "can't talk its way around these rules", but "Developers remain responsible for deciding what access to grant and where human review is needed"; Linux is in development and Windows is "on our radar".

Why it matters: a second hyperscaler in two weeks has shipped deterministic, history-aware containment for agents as open source, which gives teams running agents on developer machines a concrete control to evaluate. It is not an approval workflow.

Confidence: announcement, high (AWS primary post and GitHub repo).

## Watch list

### Country-code registry hijacks produced valid certificates for Google and other brands

Slug: `cctld-registry-hijacks-fake-certs` (feed: The Register; Google primary via Register link).

Google Security Blog (6 October, outside the window; Register coverage 7 October 20:38 UTC): attackers compromised the third-party operators of the .gh (Ghana), .sl (Sierra Leone) and .as (American Samoa) ccTLDs, "modified authoritative DNS records" and obtained unauthorised HTTPS certificates covering several Google domains and domains of other organisations; Certificate Transparency data later showed "several leading global brands and widely used online services" affected. Google blocked the certificates in Chrome via CRLSets, worked with the CAs to revoke them, and says it has "no reason to believe" the CAs did anything wrong, but "we cannot guarantee that our analysis identified every affected domain" and Chrome's interventions do not protect non-Chrome users. Recommendations: monitor CT logs across the whole domain portfolio including parked and regional ccTLD properties; publish restrictive CAA records with ACME account bindings (CAA cannot stop issuance during an active hijack but prevents reuse of cached validation afterwards).

What would make it matter: an unexpected certificate for a bank-owned domain appearing in CT logs, or a regional ccTLD operator being hit. Kept to the watch list because the incident itself is the other routine's beat; the structural point is that control of a registry defeats domain validation.

Confidence: event, high.

### Singapore's central bank issues first AI risk-management guidelines for financial institutions

Slug: `mas-ai-risk-guidelines-fis` (feed: The Register; MAS primary via Register link).

MAS media release (7 October): Guidelines on Artificial Intelligence Risk Management, consulted on in November 2025, take effect 7 October 2027 (sections 3-4), with sections 5-6 due by 7 October 2028. Expectations: board and senior management oversight using existing governance structures where adequate; AI inventories "at an appropriate level of granularity"; controls across data governance, testing, human oversight, cybersecurity, monitoring and change management; FIs "remain accountable for AI used in the services they deliver" including third-party AI, with compensating controls and the option to limit, suspend or replace a service; "The extent and sophistication of the controls should depend on FIs' risk exposure." MAS "intends to further consult the financial sector on what additional guidance on agentic AI would be useful" in 2027. The Register adds that the guidelines call for pre-deployment reviews "by parties not involved in its development" and that MAS fears agentic AI "could further amplify these risks."

What would make it matter: a regional regulator adopting the same template. Regulation is the other routine's beat; it is listed here because it is the first central-bank AI-risk rulebook with an agentic-AI follow-up announced.

Confidence: event, high.
